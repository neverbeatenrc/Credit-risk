# Credit Risk Analysis Project

An introductory MBA data-science project that analyzes the supplied loan dataset, estimates default risk with an interpretable logistic-regression model, and exports tables for a Power BI dashboard.

## Run the analysis

1. Use the shared `.venv` environment; VS Code defaults all notebooks to `.venv/Scripts/python.exe`.
2. To recreate the environment on another machine, run:

   ```powershell
   py -3.13 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

3. Use `credit_risk_analysis.ipynb` as the start page, then run each notebook in order:

   1. `01_data_cleaning.ipynb`
   2. `02_data_organization.ipynb`
   3. `03_portfolio_analysis.ipynb`
   4. `04_model_development.ipynb`
   5. `05_powerbi_prep.ipynb`

4. Import the CSV files from `powerbi_exports/` into Power BI Desktop using `POWERBI_GUIDE.md`.

Keep `credit_risk_dataset.csv` in this project folder; the numbered notebooks read and write their stage files here.

## Data Story

The dataset starts with 32,581 records. Removing 165 exact duplicates leaves 32,416 records, of which 7,089 are labeled as defaults, an observed default rate of 21.9%. This is the portfolio baseline for the analysis; the meaning of `loan_status = 1` should be confirmed against the dataset source.

Risk is not evenly distributed across the recorded loan purposes. Debt-consolidation records have the highest observed default rate at 28.7%, followed by medical at 26.8% and home-improvement at 26.2%. Venture records are lowest at 14.9%. These are descriptive differences in this dataset, not evidence that loan purpose causes default.

The logistic-regression model, evaluated on a held-out test sample, achieves ROC AUC 0.802, Gini 0.604, and KS 0.460. Five-fold cross-validation gives a mean ROC AUC of 0.806 (standard deviation 0.006), suggesting similar ranking performance across the training folds. The model therefore separates higher-risk from lower-risk records, but this does not by itself determine a lending decision.

The threshold makes that limitation concrete. At the example 0.50 probability threshold, the model flags 11.5% of test records; 74.9% of those flagged records are defaults, but it captures only 39.3% of all defaults. Lowering the threshold would catch more defaults while also flagging more records. Choosing a real threshold requires business loss assumptions, customer-impact analysis, and policy review, none of which are included in this dataset.

## Project contents

- `credit_risk_analysis.ipynb`: short start page linking the project stages.
- `01_data_cleaning.ipynb`: checks data quality, removes exact duplicates, and saves the cleaned dataset.
- `02_data_organization.ipynb`: creates analysis bands and saves the organized dataset.
- `03_portfolio_analysis.ipynb`: writes portfolio segments and WOE/IV detail to `powerbi_exports/`.
- `04_model_development.ipynb`: runs cross-validation, VIF, logistic models, scorecard-style scoring, calibration, and test-set evaluation; outputs go to `powerbi_exports/`.
- `05_powerbi_prep.ipynb`: checks the five final dashboard tables.
- `requirements.txt`: Python dependencies.
- `POWERBI_GUIDE.md`: dashboard structure, CSV meanings, and example DAX measures.
- `powerbi_exports/`: five Power BI-ready tables generated by stages 03 and 04.

## Modeling choices and limitations

- Assumes `loan_status = 1` is default and `0` is non-default; verify this with the dataset source.
- Uses a stratified holdout and cross-validation. Imputation and encoding are fitted inside the model pipeline.
- The main model excludes `person_age`, `loan_grade`, and `loan_int_rate`. Age needs careful fair-lending review; grade and rate may reflect a prior lender decision and create circularity or leakage.
- The supplied file has no dates, loss-given-default, revenue, detailed bureau tradelines, or alternate data. It cannot establish true vintage cohorts, future forecasting, temporal PSI, or profit-optimal policy.
- Thresholds, the 0-100 risk index, and the points scale are demonstrations, not approval rules or regulated credit scores.
- This project is for learning and presentation. It is not a production lending system; real use requires independent validation, governance, privacy and fair-lending review.
